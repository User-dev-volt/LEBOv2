## 9. The AutoSave Setup — Plain Explanation + Fix (per Alec's request)

**What the setup does.** Every time a Claude response ends, a **Stop hook** (`~/.claude/settings.json` →
`session-end-flush.py`) runs `auto_commit.py`, which reads this repo's `.gitaccount` and:
1. stages **all** working-tree changes (`git add -A` — literally whatever is on disk at that instant);
2. runs a safety gate (`pre_commit_gate.py`: `tsc --noEmit` + `vitest` with no NEW failures vs a ratcheting baseline);
3. if the gate passes, commits `[AutoSave] <timestamp>`;
4. **(was)** because `auto_push: true`, immediately pushed that commit to `origin/main`.

**Exactly what was wrong.**
- It snapshots the raw working tree with **no notion of a good stopping point** — it freezes whatever bytes are on
  disk when the hook fires.
- **`auto_push: true` was the dangerous multiplier:** every snapshot went straight to shared `origin/main`, so a
  transient/phantom/broken state was *published*, not just kept locally. That is how `d948556` (budget cap stripped
  by the racing writer) became a permanent ancestor of `main` on origin.
- **The gate that would have caught it didn't exist yet** when `d948556` was committed (added ~a day later in
  `24e0d92`). It is live now (baseline = the 7 standing failures) and would block *that* class today — but only
  because Epic 3 added the exact-value test. A subtle logic regression with no covering test still gets through.
- **The root cause — the racing writer — is still unidentified.** It is *not* editor format-on-save (none configured)
  and there is no Prettier/ESLint. The gate catches broken *commits*; it does nothing about *why* phantom edits appear.

**Fix applied this retro.** `auto_push: true → false` in `D:/Projects/LEBOv2/.gitaccount`. Effect: local `[AutoSave]`
snapshots keep happening (safety net + gate intact), but **nothing auto-publishes to `origin/main` anymore** —
`origin/main` only advances when Alec deliberately pushes (`/gitpush` or `git push`), so it becomes trustworthy again.
Reversible (one word); per-repo (other Second Brain projects unaffected).

**Tradeoff & options.** Unpushed local commits now stay on the machine until pushed (no automatic off-machine backup).
Handle by pushing at real checkpoints — or, if continuous off-machine backup is wanted without polluting `main`, add
a `push_branch` so autosave pushes to an `autosave/*` branch instead (small enhancement to the shared `auto_commit.py`;
not done unilaterally — awaiting Alec's go).

**To close the root cause:** add a pre-stage `git diff --stat` + timestamp log so the next phantom edit is caught with
a diff to correlate against whatever else was running; and avoid running two agent sessions on this repo concurrently.
