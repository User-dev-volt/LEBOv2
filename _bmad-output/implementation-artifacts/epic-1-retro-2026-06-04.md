## 2. What Went Well

- **Source-auditing discipline (the headline win).** After the Story 1.2 penetration trap, every
  subsequent story *opened* with a shipped-data source audit (1.3 named it a "disaster-prevention gate").
  This converted "the math is right" into "the math is right AND fed by real data." Alec: this importance
  "cannot be overstated — if stats aren't correct, the user gets nothing from the product."
- **Honest-display rule.** Unsourced stats surface honest `0.0` / `—` rather than fabricated numbers
  (Parry, minion count/HP, block effectiveness). The discipline protects the user even when data is absent.
- **Frozen parity gate + no-dead-keys rule.** Every change additive; every StatKey provably produced AND
  consumed. The scoring aggregate stayed stable while the sheet grew.
- **Review rigor every time.** Caught the penetration hybrid over-count, NaN/Inf guards, the silent
  Necrotic-resistance delta gap, the minion delivery-type case-fold. Alec: "review was great each time."
- **Clean story-to-story handoff.** Each story left explicit "for Story 1.X" notes that the next consumed
  (1.2 → 1.6 necrotic color; 1.7 → 1.8 `AllResistances` fan-in requirement).

## 3. Challenges & Growth Areas

- **Recurring defect class: *computed-but-not-sourced*.** Correct, tested math for a stat the loader never
  feeds. Appeared three times — penetration (1.2, re-opened into Tasks 9–13), StunChance (1.2, still inert),
  minion count/HP (1.5 → Story 5.5). Literal ACs ("computed") passed while the FR stayed functionally inert.
  - **Agreed root-cause fix:** the audit was catching these at *review*; it must catch them at *story creation*.
- **Single-stat-per-effect loader is the structural root cause.** `parse_node_effects` emits one stat + one
  value per effect, so multi-clause nodes ("+X% Damage. +Y% Penetration") can't be expressed — this
  *manufactured* the penetration trap and forced a brittle parser-split.
- **Brittle prose parser.** `parse_penetration_clause` splits only on `". "`, reads only the first clause,
  resolves element by substring match (`'void'` ⊂ `'avoidance'`). Inert on shipped data but unguarded.
- **Golden-count test is a weak guarantee.** It proves *how many* effects parsed, not whether any parsed
  *correctly*. A mis-valued / mis-element pen leaves the count at 185 and goes undetected.
- **Headless-env verification gaps.** tunklab (the ±2% parity authority) is JS-gated/unreachable, so EHP
  reference figures are closed-form Maxroll derivations, not live captures. NFR-10 needed a real
  `tauri dev --release` (debug build showed misleading 170ms spikes). pnpm aborted under no-TTY; stale
  Tauri `OUT_DIR` needed `cargo clean`.
- **14 pre-existing UI test failures** carried as a baseline the whole epic (AppHeader, RightPanel,
  ProviderSelector, Settings, SkillTreeCanvas, TreeControls — jsdom/Headless-UI/canvas env). Every story
  had to prove "zero NEW failures" against this noise.

### Note on the void-penetration confusion (clarified in-retro)
The mechanic was never the problem — penetration is modeled correctly against a documented **0%-resistance
reference target** (`damage × (1 + pen/100)`), the same sheet-DPS convention build planners use. The actual
problem was **sourcing + parsing**: the loader had no `PENETRATION` branch (so `pen_mult` was always 1.0),
the dominant pen tags (Void/Holy/Chaos/Elemental) lacked StatKeys or aren't modeled LE types, and the
single-stat-per-effect loader couldn't emit damage + penetration from one node.
